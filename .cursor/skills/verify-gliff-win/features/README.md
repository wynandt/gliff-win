# Client verification map

Native journeys that need a Windows session are unexecuted unless a map
entry records a hardware gate. Host tests, picture judges and cross-builds
are not native UI evidence. Start with the parent skill's isolated launch
and doctor. Preserve proof after cleanup and record each skipped entry
point separately.

- [Connect](connect.md): address bar, command-line targets, ssh start, retry.
- [Failure panel](failure-panel.md): the panel when a connection fails.
- [Tabs](tabs.md): strip, dots, menus, switch chords, several sessions.
- [Fullscreen](fullscreen.md): borderless fullscreen and the hidden strip.
- [Keyboard](keyboard.md): grab, release and switch chords, Super+L, local chords.
- [Input](input.md): graph press/cancel and pointer through the stats readout.
- [Clipboard](clipboard.md): text, pictures and files in both directions.
- [Settings](settings.md): flags, config file, connection settings, `--print-settings`.
- [Stats](stats.md): graph toggle, live/idle metrics, JSON sample.

A configured authorized server, SSH trust and an unlocked disposable Windows
session are preconditions, not things these recipes may silently create.
